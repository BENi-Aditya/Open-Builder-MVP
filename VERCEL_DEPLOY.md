# Deploying OPENBUILDER to Vercel

To deploy this project to Vercel and ensure all logic (Auth, Database, etc.) works perfectly, follow these steps:

## 1. Environment Variables
When you import your project into Vercel, you **MUST** add the following environment variables in the Vercel Dashboard (**Settings > Environment Variables**):

| Key | Value |
| :--- | :--- |
| `VITE_SUPABASE_URL` | Your Supabase Project URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Your Supabase Anon Key |
| `SUPABASE_URL` | Same as `VITE_SUPABASE_URL` |
| `SUPABASE_PUBLISHABLE_KEY` | Same as `VITE_SUPABASE_PUBLISHABLE_KEY` |

## 2. Vercel Project Settings
I have updated the project to use the **TanStack Start (Nitro)** deployment pattern which is the most stable for SSR.

**Settings to use in Vercel Dashboard:**
- **Framework Preset**: `Other` (Vercel will automatically detect the Nitro output).
- **Build Command**: `npm run build`
- **Output Directory**: Leave empty (Vercel will use `.vercel/output` automatically).
- **Install Command**: `npm install --legacy-peer-deps`

## 3. Why the 500 error?
The 500 error usually happens for two reasons:
1. **Missing Environment Variables**: Ensure all 4 Supabase variables mentioned above are added to Vercel.
2. **Output Directory Mismatch**: If you manually set the output directory to `dist`, Vercel might not find the server functions generated by Nitro. By leaving it empty and using the `Other` preset, Vercel will correctly pick up the Build Output API structure in `.vercel/output`.
3. **Missing Files**: If a resource like `favicon.ico` is missing, the request might fall through to the server function. I have updated the server to handle these cases more gracefully.
